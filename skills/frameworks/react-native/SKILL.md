# React Native

Assumes React Native 0.73+ (New Architecture default from 0.76) and, when present, Expo SDK 50+ with expo-router. Component-level React guidance lives in the `react` skill; this skill covers the mobile runtime, navigation, native integration and builds. Check versions with `npx react-native --version` or `npx expo --version`.

## When to use

- Creating screens, navigation flows, lists, forms, gestures and animations in a mobile app.
- Using device APIs (camera, location, notifications, storage, haptics), permissions, deep links.
- Adding or configuring native modules, config plugins, `ios/` or `android/` changes.
- Fixing performance (jank, slow lists, bridge traffic), Metro/Hermes build issues, platform-specific bugs.
- Writing tests and producing builds (EAS, Xcode, Gradle), OTA updates.

## Project conventions to detect first

1. Expo vs bare:
   - Expo managed (CNG): `expo` in deps, `app.json`/`app.config.ts` with an `expo` key, no committed `ios/`/`android/` (or they are gitignored and regenerated by `npx expo prebuild`). Native changes go through config plugins, never by editing generated folders.
   - Expo with committed native folders: `expo` present and `ios/`/`android/` tracked. Native edits are allowed; `expo prebuild` would overwrite them, so check whether the team runs it.
   - Bare RN: no `expo` (or only `expo` modules via `install-expo-modules`), `ios/Podfile`, `android/build.gradle`, `react-native.config.js`.
2. RN and Expo SDK versions (`react-native`, `expo` in `package.json`). `newArchEnabled` in `app.json`/`gradle.properties`/`Podfile.properties.json`; libraries must support the New Architecture when it is on. Hermes is the default engine.
3. Navigation: `expo-router` (file routes in `app/`), `@react-navigation/native` with `@react-navigation/native-stack`/`bottom-tabs`/`drawer` (v6 or v7 static API `createStaticNavigation`), or `react-native-navigation`.
4. Styling: `StyleSheet.create`, `nativewind` (`className`, `tailwind.config.js`, `global.css`), `tamagui`, `react-native-unistyles`, `styled-components/native`, `@shopify/restyle`. Theme/`useColorScheme` handling.
5. State/data: TanStack Query, Zustand, Redux Toolkit, Jotai, MMKV (`react-native-mmkv`) or AsyncStorage, `expo-secure-store` for secrets, `expo-sqlite`/WatermelonDB/Drizzle.
6. Lists and animation libs: `@shopify/flash-list` (v1 needs `estimatedItemSize`; v2 does not), `react-native-reanimated` (v3 babel plugin `react-native-reanimated/plugin`; v4 requires `react-native-worklets` and its plugin), `react-native-gesture-handler`, `moti`.
7. Tests: `jest.config.js` with preset `jest-expo` or `react-native`, `@testing-library/react-native`, `jest-native` matchers (built into RNTL v12.4+), Maestro (`.maestro/*.yaml`) or Detox for e2e.
8. Builds: `eas.json` profiles, `expo-updates` (channels, `runtimeVersion` policy), Fastlane, Xcode workspace name, `android/app/build.gradle` `applicationId`, signing config, `.env` handling (`EXPO_PUBLIC_*` or `react-native-config`).
9. Lint/TS: `eslint-config-expo` or `@react-native/eslint-config`, `tsconfig.json` extending `expo/tsconfig.base`, path alias `@/` via `tsconfig` `paths` (Expo) or `babel-plugin-module-resolver`.

## Core guidance

### Components and styling

```tsx
import { Pressable, StyleSheet, Text, View, useWindowDimensions } from 'react-native';
import { useSafeAreaInsets } from 'react-native-safe-area-context';

export function Header({ title, onBack }: { title: string; onBack?: () => void }) {
  const insets = useSafeAreaInsets();
  const { width } = useWindowDimensions();
  return (
    <View style={[styles.root, { paddingTop: insets.top, width }]}>
      {onBack ? (
        <Pressable onPress={onBack} accessibilityRole="button" accessibilityLabel="Go back" hitSlop={12}
          style={({ pressed }) => [styles.back, pressed && styles.pressed]}>
          <Text style={styles.backText}>Back</Text>
        </Pressable>
      ) : null}
      <Text style={styles.title} numberOfLines={1}>{title}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  root: { flexDirection: 'row', alignItems: 'center', gap: 12, paddingHorizontal: 16 },
  back: { padding: 8 },
  pressed: { opacity: 0.6 },
  backText: { fontSize: 16 },
  title: { flex: 1, fontSize: 20, fontWeight: '600' },
});
```

- Only `<Text>` can contain strings; raw text inside `<View>` throws. Use `<Pressable>` (not `TouchableOpacity`) for new touch targets with `accessibilityRole`, `accessibilityLabel`, and `hitSlop` for small targets.
- Flexbox defaults differ from the web: `flexDirection: 'column'`, `flex: 1` to fill, `alignItems: 'stretch'`. No CSS units, no cascading, no `display: grid`. `gap` works (0.71+).
- Safe areas via `react-native-safe-area-context` (`SafeAreaProvider` at the root, `useSafeAreaInsets` or `SafeAreaView` from that package, not the core one).
- Platform splits: `Platform.OS`, `Platform.select({ ios, android, default })`, and file suffixes `Component.ios.tsx` / `.android.tsx` / `.web.tsx` / `.native.tsx`.
- Images: `expo-image` (`Image` with `source`, `contentFit`, `placeholder`, caching) in Expo; core `Image` needs explicit `width`/`height` for remote sources.
- Keyboard: `KeyboardAvoidingView` with `behavior={Platform.OS === 'ios' ? 'padding' : 'height'}` or `react-native-keyboard-controller`; dismiss with `Keyboard.dismiss()` on scroll/tap.
- Fonts: `expo-font` (`useFonts` or `expo-font` config plugin for build-time embedding); bare projects link via `react-native.config.js` assets + `npx react-native-asset`.
- Dark mode: `useColorScheme()` and a theme object; with NativeWind use `dark:` variants.

### Navigation

Expo Router (file-based, built on React Navigation):

```
app/
  _layout.tsx          # root Stack; providers go here
  index.tsx            # "/"
  (tabs)/_layout.tsx   # <Tabs> group, URL stays "/..."
  (tabs)/feed.tsx
  posts/[id].tsx       # "/posts/:id"
  +not-found.tsx
```

```tsx
// app/_layout.tsx
import { Stack } from 'expo-router';
export default function RootLayout() {
  return <Stack screenOptions={{ headerShown: false }}><Stack.Screen name="(tabs)" /><Stack.Screen name="posts/[id]" options={{ presentation: 'modal' }} /></Stack>;
}
// app/posts/[id].tsx
import { useLocalSearchParams, Link, router } from 'expo-router';
const { id } = useLocalSearchParams<{ id: string }>();
<Link href={{ pathname: '/posts/[id]', params: { id: '42' } }}>Open</Link>; router.push('/posts/42'); router.back();
```

- Typed routes: `experiments: { typedRoutes: true }` in `app.json` generates `Href` types. `expo-router` also handles deep links from the `scheme` in `app.json` and universal links via `associatedDomains`/`intentFilters`.
- Providers (query client, theme, gesture handler root) wrap the root layout's `<Stack>`. Use `Redirect` or conditional `Stack.Screen` lists for auth gating; `useSegments`/`usePathname` for route-aware logic.

React Navigation (bare or non-router Expo):

```tsx
const Stack = createNativeStackNavigator<RootStackParamList>();
<NavigationContainer linking={linking}>
  <Stack.Navigator>
    <Stack.Screen name="Home" component={Home} />
    <Stack.Screen name="Post" component={Post} options={({ route }) => ({ title: route.params.title })} />
  </Stack.Navigator>
</NavigationContainer>
```

- Type params with a `ParamList` and `NativeStackScreenProps<RootStackParamList, 'Post'>`; `useNavigation()`/`useRoute()` typed via a global declaration. Prefer `native-stack` over the JS `stack` for performance. v7 offers a static API (`createStaticNavigation`) with inferred types; check which the project uses.
- Wrap the app in `GestureHandlerRootView` when using gesture handler or drawer.

### Lists and performance

- Long lists use `FlatList` or `@shopify/flash-list`, never `ScrollView` + `.map()`. Provide `keyExtractor`, a memoised `renderItem` component (`React.memo`), stable `data` references, and `getItemLayout` for fixed heights. FlashList: `estimatedItemSize` in v1; v2 (RN New Architecture only) drops it.
- Move expensive work off the JS thread: Reanimated worklets for animations/gestures, `InteractionManager.runAfterInteractions` for deferrable work, `expo-image` for decoding, avoid `console.log` in hot paths (remove in release via `babel-plugin-transform-remove-console`).
- Measure in a release build (`npx expo run:ios --configuration Release`, `npx react-native run-android --mode release`) with the Performance Monitor (dev menu) and React DevTools profiler via React Native DevTools (`j` in the Metro terminal, RN 0.76+).
- Avoid inline object/array/function props on list rows and heavy `useEffect` chains that set state during scroll. Memoise selectors for stores.
- Images: correct `resizeMode`/`contentFit`, sized thumbnails from the server, `expo-image` cache policy.
- Startup: lazy-load heavy screens (`React.lazy` works with Suspense), keep the root layout light, enable Hermes (default), check bundle size with `npx expo export --dump-sourcemap` + source-map-explorer or `npx react-native-bundle-visualizer`.

### Animations and gestures

```tsx
import Animated, { useSharedValue, useAnimatedStyle, withSpring } from 'react-native-reanimated';
import { Gesture, GestureDetector } from 'react-native-gesture-handler';

const x = useSharedValue(0);
const pan = Gesture.Pan().onChange((e) => { x.value += e.changeX; }).onEnd(() => { x.value = withSpring(0); });
const style = useAnimatedStyle(() => ({ transform: [{ translateX: x.value }] }));
<GestureDetector gesture={pan}><Animated.View style={[styles.box, style]} /></GestureDetector>
```

- Reanimated runs worklets on the UI thread; everything inside `useAnimatedStyle`/gesture callbacks must be a worklet (automatic with the babel plugin) and call JS via `runOnJS`. Reanimated 3 needs `plugins: ['react-native-reanimated/plugin']` last in `babel.config.js`; Reanimated 4 moves the plugin to `react-native-worklets/plugin`. Check the installed major and its installation guide.
- Layout animations: `entering={FadeIn}`/`exiting`, `layout={LinearTransition}`. Core `Animated` API is acceptable for simple fades with `useNativeDriver: true`, but prefer Reanimated when it is already installed.
- Reset the Metro cache after adding the plugin: `npx expo start --clear` or `npx react-native start --reset-cache`.

### Platform APIs, permissions, storage

- Expo modules first: `expo-camera`, `expo-location`, `expo-notifications`, `expo-haptics`, `expo-linking`, `expo-file-system`, `expo-secure-store`, `expo-sqlite`, `expo-av`/`expo-audio`/`expo-video`, `expo-local-authentication`. Install with `npx expo install <pkg>` so versions match the SDK.
- Permissions: each module exposes `useXPermissions()`/`requestXPermissionsAsync()`. Usage strings (`NSCameraUsageDescription`) and Android permissions are set through the module's config plugin in `app.json` `plugins`, or in `Info.plist`/`AndroidManifest.xml` in bare projects. Missing strings crash iOS at runtime or fail App Store review.
- Storage: `react-native-mmkv` (sync, fast) or `@react-native-async-storage/async-storage` (async, simple) for preferences; `expo-secure-store`/Keychain for tokens. Never store secrets in `EXPO_PUBLIC_*` or the JS bundle.
- Env: `EXPO_PUBLIC_*` variables are inlined into the client bundle at build time (SDK 49+). Server secrets belong on a server. Bare projects use `react-native-config` or `babel-plugin-transform-inline-environment-variables`.
- Networking: `fetch` with `AbortController`; Android emulators reach the host at `10.0.2.2`; cleartext HTTP needs `usesCleartextTraffic` in dev only.
- Deep links: `scheme` in `app.json`; `Linking.getInitialURL()`/`addEventListener('url')` or router linking config.

### Native modules and config

- Expo Modules API for new native code: `npx create-expo-module@latest --local` creates `modules/<name>` with Swift/Kotlin and a TS wrapper; autolinked in dev builds. Prefer it over TurboModules in Expo projects; TurboModules (`codegenConfig` in `package.json`, Codegen specs in `specs/`) for bare projects without Expo modules.
- Config plugins (`app.config.ts` `plugins: [['./plugins/withFoo', { opt }]]`, using `@expo/config-plugins` `withInfoPlist`/`withAndroidManifest`/`withDangerousMod`) are the only sanctioned way to change native projects under CNG. Verify with `npx expo prebuild --clean` and diff the output.
- Anything beyond Expo Go's bundled modules requires a development build: `npx expo run:ios|android` locally or `eas build --profile development`, then `npx expo start --dev-client`.
- Bare: after adding a native dependency run `npx pod-install` (iOS) and rebuild; Gradle picks up autolinking on the next build. Keep `ios/Podfile.lock` committed.
- Upgrades: Expo `npx expo install expo@^<sdk> --fix` then `npx expo-doctor`; bare uses the Upgrade Helper (https://react-native-community.github.io/upgrade-helper/) to apply the native diff.

## Common tasks

### Add a screen

1. Expo Router: `app/<route>.tsx` (or inside a group) exporting a default component; register options in the parent `_layout.tsx` if needed. React Navigation: component + `Stack.Screen` + param list entry.
2. Wrap content in a safe-area-aware container; handle loading/error/empty states; make the primary list a `FlatList`/`FlashList`.
3. Link from existing screens with `<Link>`/`router.push` or `navigation.navigate`.
4. Test with RNTL: render inside the providers the screen needs (a `renderWithProviders` helper).

### Add a device capability

1. `npx expo install expo-<module>` (or the community package in bare; then `pod-install`).
2. Add the config plugin and permission strings in `app.json`; rebuild the dev client (`npx expo run:ios` / `eas build --profile development`); Expo Go will not have it unless bundled.
3. Request permission at the moment of use; handle `denied`/`undetermined`; provide a path to Settings (`Linking.openSettings()`).

### Fix a slow list

1. Confirm in a release build; profile with the Performance Monitor (JS FPS vs UI FPS).
2. Memoise the row component, remove inline closures, pass primitives not objects, add `keyExtractor` and `getItemLayout` or switch to FlashList.
3. Trim images (server-side sizing, `expo-image`), paginate (`onEndReached`), reduce `windowSize`/`maxToRenderPerBatch` if memory-bound.

### Set up builds and OTA

1. `npx eas init` then `eas build:configure` creates `eas.json`; profiles: `development` (`developmentClient: true`, `distribution: internal`), `preview` (`distribution: internal`), `production` (store).
2. `eas build --platform all --profile production`; `eas submit -p ios|android`. Credentials are managed by EAS unless `credentialsSource: 'local'`.
3. OTA: `npx expo install expo-updates`, `eas update:configure`, then `eas update --channel production --message "fix"`; JS-only changes ship instantly, native changes need a new build (`runtimeVersion` policy `appVersion` or `fingerprint`).
4. Bare: iOS archive in Xcode or `xcodebuild`/Fastlane; Android `cd android && ./gradlew bundleRelease` with signing in `~/.gradle/gradle.properties`.

### Write a test

```tsx
import { render, screen, userEvent } from '@testing-library/react-native';
import { Counter } from './Counter';

test('increments', async () => {
  const user = userEvent.setup();
  render(<Counter />);
  await user.press(screen.getByRole('button', { name: /increment/i }));
  expect(screen.getByText('Count: 1')).toBeOnTheScreen();
});
```

- Jest preset `jest-expo` (Expo) or `react-native`; add `transformIgnorePatterns` entries for untranspiled libraries when Jest fails on `import` syntax. Mock native modules the library documents (`jest.mock('react-native-reanimated', () => require('react-native-reanimated/mock'))`), and router hooks (`jest.mock('expo-router')`).
- Query by role/text/`testID`; avoid snapshot tests of whole screens.
- E2E: Maestro flows (`maestro test .maestro/login.yaml`) are the simplest; Detox for deeper control. Both need a built app.

## Pitfalls

- Text outside `<Text>`; `onPress` on a `View`; forgetting `keyExtractor` or using the index for mutable lists.
- Running native-dependent code in Expo Go and seeing `Native module cannot be null`; build a dev client.
- Editing `ios/`/`android/` in a CNG project; changes vanish on the next `prebuild`. Use config plugins.
- Installing packages with `npm install` instead of `npx expo install` (version mismatch with the SDK), or mixing package managers (duplicate lockfiles).
- Reanimated babel plugin missing or not last; worklet errors (`Tried to synchronously call a non-worklet function`); fix the plugin and clear Metro cache.
- Secrets in `EXPO_PUBLIC_*` or `app.json` `extra` (they ship in the bundle).
- Using `Dimensions.get()` once at module level (does not update on rotation/foldables); use `useWindowDimensions`.
- Absolute positioning with the core `SafeAreaView` on Android (no insets); use `react-native-safe-area-context`.
- Large `useEffect` fetches without cancellation on screens that unmount quickly, causing state updates after unmount.
- Forgetting `GestureHandlerRootView`, so gestures silently do nothing on Android.
- Upgrading RN by editing `package.json` only; native templates must be upgraded too (Upgrade Helper / `expo install --fix`).
- Assuming web CSS behaviour (percent heights, `position: fixed`, `z-index` across siblings, text wrapping without `flexShrink: 1`).

## Verification

```bash
cat package.json | jq .scripts
npx expo-doctor                          # Expo: dependency/version/config health
npx expo install --check                 # list SDK-incompatible versions (--fix to apply)
npx tsc --noEmit
npx expo lint   # or: npx eslint .
npx jest
npx expo start --clear                   # dev server with a clean Metro cache
npx expo run:ios && npx expo run:android # compile native projects locally (bare: npx react-native run-ios / run-android)
npx expo export --platform all           # production JS bundle sanity check
eas build --profile preview --platform all --non-interactive   # cloud build when EAS is configured
```
