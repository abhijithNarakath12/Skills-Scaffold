# Hono

Assumes Hono 4.x. Hono is built on Web Standards (`Request`, `Response`, `fetch`), so the same app runs on every runtime through a thin adapter; keep runtime-specific code at the entry point.

## When to use

- Adding routes, middleware, validators, or typed RPC endpoints to a Hono app.
- Deploying to Cloudflare Workers/Pages, Bun, Deno, Node (`@hono/node-server`), Vercel, Netlify, AWS Lambda, Fastly or Supabase Functions.
- Sharing types between a Hono backend and a frontend via `hc` (Hono client).
- Writing tests that call the app directly with `app.request()`.
- Not for Express-style apps or Next.js route handlers unless they explicitly embed Hono.

## Project conventions to detect first

1. Runtime and adapter: `@hono/node-server` (Node), `wrangler.toml`/`wrangler.jsonc` (Cloudflare Workers), `bun run` scripts, `deno.json`, `hono/vercel`, `hono/aws-lambda`, `hono/netlify`. The entry file exports `app` (Workers/Bun/Deno: `export default app`) or calls `serve({ fetch: app.fetch, port })` (Node).
2. Validator: `@hono/zod-validator` (`zValidator`), `@hono/valibot-validator`, `@hono/typebox-validator`, or Hono's built-in `validator()`; and `@hono/zod-openapi` or `hono-openapi` if OpenAPI docs are generated.
3. Router choice: default `Hono()` uses SmartRouter; `hono/tiny`, `hono/quick` (Cloudflare Workers without per-isolate warm-up) are deliberate choices; do not swap them.
4. Env bindings typing: `new Hono<{ Bindings: Env; Variables: { user: User } }>()`; `Env` generated by `wrangler types` (`worker-configuration.d.ts`) on Cloudflare.
5. Layout: single `src/index.ts` for small apps; `src/routes/*.ts` returning `new Hono()` sub-apps mounted with `app.route('/users', users)`; `src/middleware/`. For RPC, routes are chained (`const app = new Hono().get(...).post(...)`) and `export type AppType = typeof app`.
6. Frontend/JSX: `hono/jsx`, `hono/jsx-renderer`, HonoX (file-based routing, `app/routes/`), or a separate SPA consuming the RPC client.
7. Tests: `vitest` (with `@cloudflare/vitest-pool-workers` on Workers), `bun test`, or `node --test`.

## Core guidance

### App and routing

```ts
import { Hono } from 'hono';
import { logger } from 'hono/logger';
import { cors } from 'hono/cors';
import { HTTPException } from 'hono/http-exception';

type Env = { Bindings: { DB: D1Database; JWT_SECRET: string }; Variables: { userId: string } };

const app = new Hono<Env>();
app.use(logger());
app.use('/api/*', cors({ origin: ['https://app.example.com'] }));

app.get('/health', (c) => c.json({ ok: true }));
app.route('/api/users', usersRoutes);

app.notFound((c) => c.json({ error: 'Not Found' }, 404));
app.onError((err, c) => {
  if (err instanceof HTTPException) return err.getResponse();
  console.error(err);
  return c.json({ error: 'Internal Server Error' }, 500);
});

export default app;
```

- Handlers return a `Response`: `c.json()`, `c.text()`, `c.html()`, `c.body()`, `c.redirect()`, `c.notFound()`. Set status as the second argument (`c.json(data, 201)`).
- Path params `c.req.param('id')`, query `c.req.query('q')` / `c.req.queries('tag')`, headers `c.req.header('authorization')`, body `await c.req.json()` / `.parseBody()` / `.formData()`; prefer validated `c.req.valid('json')`.
- Route groups: build a sub-app in its own file and mount with `app.route(path, sub)`; or `app.basePath('/api')`.
- Wildcards `/*`, optional `/:id?`, regex `/:id{[0-9]+}`. Register more specific routes before `/*` catch-alls; middleware registered with `app.use(path, mw)` must be registered before the routes it should cover.
- Multiple methods: `app.on(['GET', 'HEAD'], '/x', h)`; all: `app.all()`.

### Middleware

```ts
import { createMiddleware } from 'hono/factory';

export const auth = createMiddleware<Env>(async (c, next) => {
  const token = c.req.header('authorization')?.replace('Bearer ', '');
  if (!token) throw new HTTPException(401, { message: 'Missing token' });
  const payload = await verify(token, c.env.JWT_SECRET); // hono/jwt
  c.set('userId', payload.sub as string);
  await next();
});
app.use('/api/*', auth);
```

- Always `await next()`; code after it runs on the way out (set response headers, timing).
- `c.set`/`c.get` for per-request values typed via `Variables`; `c.env` for runtime bindings/secrets (Workers) or `process.env` substitutes (`import { env } from 'hono/adapter'; env(c).FOO` works across runtimes).
- Built-in middleware under `hono/*`: `logger`, `cors`, `csrf`, `secure-headers`, `etag`, `cache`, `compress`, `basic-auth`, `bearer-auth`, `jwt`, `body-limit`, `timeout`, `request-id`, `pretty-json`, `trailing-slash`, `ip-restriction`, `combine` (`some`/`every`/`except`). Check https://hono.dev/docs/middleware/builtin before writing your own.
- Third-party: `@hono/*` packages (zod-validator, swagger-ui, sentry, clerk-auth, etc.).

### Validation

```ts
import { zValidator } from '@hono/zod-validator';
import { z } from 'zod';

const createUser = z.object({ email: z.string().email(), name: z.string().min(1) });

const users = new Hono<Env>()
  .post('/', zValidator('json', createUser), async (c) => {
    const body = c.req.valid('json'); // typed
    const user = await c.env.DB.prepare('INSERT ...').bind(body.email, body.name).run();
    return c.json(user, 201);
  })
  .get('/:id', zValidator('param', z.object({ id: z.coerce.number() })), (c) => {
    const { id } = c.req.valid('param');
    return c.json({ id });
  });
export default users;
export type UsersType = typeof users;
```

- Targets: `'json' | 'form' | 'query' | 'param' | 'header' | 'cookie'`. Query and param values are strings; use `z.coerce`.
- Custom error response: third argument `(result, c) => { if (!result.success) return c.json({ errors: result.error.flatten() }, 400); }`.
- The validator must run before the handler that calls `c.req.valid()`.

### RPC (typed client)

- Chain route definitions on one `Hono` instance so the type captures all routes; `app.route()` of sub-apps also carries types if the sub-app is chained.
- Server: `export type AppType = typeof app`. Client:

```ts
import { hc } from 'hono/client';
import type { AppType } from '../server/app';
const client = hc<AppType>('https://api.example.com/');
const res = await client.api.users[':id'].$get({ param: { id: '1' } });
if (res.ok) { const user = await res.json(); } // typed
```

- Return responses with `c.json()` and let TypeScript infer; explicit `Response` types break inference. Use `c.json(data, 404)` with literal status so the client sees status-specific types.
- For large apps compile times grow; split into typed sub-apps and use `hc` per sub-app, or use `hcWithType` pattern from the docs. Keep server and client in a shared `tsconfig` project reference or monorepo.

### Runtime adapters

| Runtime | Entry |
|---|---|
| Node | `import { serve } from '@hono/node-server'; serve({ fetch: app.fetch, port: 3000 })`; static files via `@hono/node-server/serve-static` |
| Bun | `export default { port: 3000, fetch: app.fetch }`; `hono/bun` for `serveStatic` |
| Deno | `Deno.serve(app.fetch)`; `hono/deno` for `serveStatic` |
| Cloudflare Workers | `export default app` (or `{ fetch: app.fetch, scheduled }`); bindings via `c.env`; `wrangler dev`/`wrangler deploy` |
| Cloudflare Pages | `functions/[[route]].ts` with `import { handle } from 'hono/cloudflare-pages'; export const onRequest = handle(app)` |
| Vercel | `import { handle } from 'hono/vercel'; export const GET = handle(app)` in `api/[[...route]].ts` |
| AWS Lambda | `import { handle } from 'hono/aws-lambda'; export const handler = handle(app)` |
| Netlify | `import { handle } from 'hono/netlify'; export default handle(app)` |

- Keep `app.ts` runtime-agnostic and create one entry file per runtime.
- Use `c.executionCtx.waitUntil(promise)` for background work on Workers; it throws on runtimes without an execution context, so guard it.
- Use `hono/adapter`'s `getRuntimeKey()` and `env(c)` for cross-runtime environment access.

### Error handling

- Throw `new HTTPException(status, { message, res?, cause? })` from handlers/middleware; `app.onError` turns it into a response with `err.getResponse()`.
- Define a single `app.onError` at the root; sub-app `onError` handlers only apply to their routes.
- Unhandled rejections in `waitUntil` do not fail the response; log them.

### Helpers and extras

- `hono/cookie`: `getCookie`, `setCookie`, `getSignedCookie`; `hono/jwt`: `sign`, `verify`, `decode`; `hono/streaming`: `stream`, `streamText`, `streamSSE`; `hono/websocket` via runtime helpers (`hono/cloudflare-workers` `upgradeWebSocket`, `@hono/node-ws`).
- JSX: `import type { FC } from 'hono/jsx'`, `c.html(<Page />)`; `jsxRenderer` middleware for layouts; set `"jsx": "react-jsx", "jsxImportSource": "hono/jsx"` in `tsconfig.json`.
- OpenAPI: `@hono/zod-openapi` (`OpenAPIHono`, `createRoute`) + `@hono/swagger-ui`.

## Common tasks

### Create a project

```bash
npm create hono@latest my-app   # pick a template: nodejs, bun, deno, cloudflare-workers, vercel, aws-lambda, x-basic ...
```

### Add an endpoint

1. Add a zod schema and route to the resource's sub-app, chained for RPC typing.
2. Use `c.req.valid()` for inputs and return `c.json(data, status)`.
3. Mount in `app.route()` if new; add middleware (auth) at the sub-app or path level.
4. Test with `app.request()`; update the client types (automatic if `AppType` is exported).

### Add auth

- JWT: `import { jwt } from 'hono/jwt'; app.use('/api/*', jwt({ secret: c => c.env.JWT_SECRET }))` requires a function form when the secret comes from `c.env`; the payload is at `c.get('jwtPayload')`.
- Bearer/API key: `bearerAuth({ verifyToken: async (token, c) => ... })`.
- Session cookies: `getSignedCookie`/`setSignedCookie` with `httpOnly`, `secure`, `sameSite: 'Lax'`.

### Write a test

```ts
import { describe, it, expect } from 'vitest';
import app from '../src/app';

it('creates a user', async () => {
  const res = await app.request('/api/users', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ email: 'a@b.co', name: 'A' }),
  }, { DB: fakeDb, JWT_SECRET: 'test' }); // third argument = env bindings
  expect(res.status).toBe(201);
  expect(await res.json()).toMatchObject({ email: 'a@b.co' });
});
```

On Cloudflare use `@cloudflare/vitest-pool-workers` and `import { env } from 'cloudflare:test'` for real D1/KV bindings; or `testClient(app)` from `hono/testing` for a typed test client.

### Deploy to Cloudflare Workers

```bash
npx wrangler types      # regenerate Env bindings type
npx wrangler dev        # local
npx wrangler deploy
npx wrangler secret put JWT_SECRET
```

## Pitfalls

- Registering middleware after routes, so it never runs for them.
- Forgetting `await next()` in middleware (response is empty or hangs).
- Reading the body twice (`c.req.json()` after a validator consumed it); use `c.req.valid()`.
- Non-chained routes (`app.get(...)` as statements) lose RPC types; chain with `.get().post()` or build sub-apps.
- Accessing `process.env` on Workers; use `c.env` or `env(c)`.
- Doing async work after returning the response without `waitUntil` on Workers (it is cancelled).
- `cors()` after the route or missing OPTIONS handling; `cors` middleware handles preflight only for the paths it is mounted on.
- Returning plain objects instead of `c.json()`; handlers must return a `Response`.
- Treating `c.req.query()` values as numbers without coercion.
- Large handlers in a single file when the RPC type gets slow to compute; split sub-apps.

## Verification

```bash
cat package.json | jq .scripts
npx tsc --noEmit                 # catches RPC type breaks between server and client
npm test                         # vitest / bun test
npm run dev                      # tsx watch / wrangler dev / bun --hot

```
